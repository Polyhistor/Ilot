Architecture Recommendation

Based on what you described — dynamic service catalog, admin control, SEO URLs, and AI WhatsApp — here's what I recommend:

Recommended Stack
Vercel
Hosting + serverless API routes. Zero config for Next.js. Scales automatically. Free tier covers most early traffic.
Supabase (PostgreSQL)
Database + auth + admin dashboard. Client can manage services directly via Supabase Studio — no custom CMS needed. Free tier, generous limits.
Next.js ISR / SSR
Each service page (e.g. /visa/tourist-visa) is server-rendered for SEO. Pages revalidate automatically when DB changes.
Data Model (simplified)
categories → 7 rows (Visa, Legal…)
services → many per category
id, category_id, title, slug,
description, price, whatsapp_msg,
is_active, sort_order
URL Structure
/ ← homepage
/visa ← category pillar
/visa/tourist-visa ← service page
/legal/contract-review ← service page
AI WhatsApp CTA
Each service page has a pre-filled WhatsApp link that sends the service name + user intent to your AI bot. The bot handles the conversation from there. We store the WhatsApp message template per service in the DB.
✓
This covers everything you described: dynamic SEO URLs, client-managed content, 20+ services per category, and per-service WhatsApp AI routing — with no third-party CMS costs.
